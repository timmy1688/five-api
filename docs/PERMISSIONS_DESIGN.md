# 轻量多租户权限设计

采用两个固定角色：platform_admin、tenant。参考 [LiteLLM 的租户边界](https://docs.litellm.ai/docs/proxy/multi_tenant_architecture) 和 [访问控制](https://docs.litellm.ai/docs/proxy/access_control)，按当前 MVP 范围实现单层 Tenant、一个租户一个账号，不实现组织、成员、动态角色、权限勾选、SSO 或在线支付。

## 身份与资源

| 身份 | 能力 |
| --- | --- |
| 平台管理员 | 创建客户账号，设置统一售价、渠道、额度、共享限流和模型范围，管理平台配置与故障；可停用或撤销客户 Key |
| 租户账号 | 修改本人密码，创建、限制、停用、撤销自己的 Key，查看所属用量和客户费用；不能创建账号 |
| 推理 Key | 只调用授权模型的推理接口，不具备创建其他 Key 或访问后台的权限 |

角色和账号的 tenant_id 创建后不可改变。客户账号只有一个业务启停入口 Tenant.is_enabled。平台管理员不绑定客户租户；管理员自用 Key 自动归入 is_system 的内部额度空间，不出现在客户开户列表中。客户 Key 由租户自行创建，不提供管理员代客户创建入口。

所有 APIKey 都有不可变的 tenant_id。内部空间同样执行 Key 摘要鉴权、模型范围、配额与日志规则，不提供无归属 Key。客户请求不能传入角色、租户归属、已用金额、报价、重置周期或审计策略。

## 凭证

管理接口采用密码登录换取默认 60 分钟 JWT，固定 aud=five-api-management。每次读取数据库角色、状态和 token_version；用户自己添加 JWT role/tenant_id 不改变授权。改密或人工重置密码撤销旧 JWT；临时、默认密码首次使用必须修改。无人值守管理程序安全保存登录凭据用于到期后重新登录，不新增 PAT。

推理 Key 采用安全随机生成，数据库只存 SHA-256 摘要和前缀；明文只在创建响应展示一次，响应 no-store，前端关闭后清除，不保存到浏览器存储。JWT 不能代替推理 Key，推理 Key 不能管理账号或其他 Key。

上游凭据使用独立 ENCRYPTION_KEY 加密，JWT 使用 SECRET_KEY 签名。主密钥位于数据库外的文件或环境变量，不再回写数据库；网关容器未配置时使用内置公开加密密钥和每次启动随机的 JWT 密钥。已有密文但缺失或不匹配秘密时拒绝启动。迁移与恢复见 [运维文档](OPERATIONS.md)。

## 额度与限流

客户额度是累计美元上限，新租户默认 0、不自动月重置。平台人工调整上限，要求 reason 与 UUID operation_id；同 ID 重试幂等，不同内容返回 409。调整不得低于已用加占用；需要冻结时停用租户。

多个 Key 共享总额；Key 的 -1 表示不另设该 Key 上限，不能增加客户总余额。撤销、更换、新建 Key 不清空租户历史已用金额。存量周期配置按迁移保留，新客户不开放周期编辑。

新租户默认共享 120 RPM、100,000 TPM、10 并发，可设正数或显式 -1 不限。Key 可设置更严格的自身限制，即使 Key 设置不限，也仍受租户限制。默认最多 100 把未撤销 Key，创建 20 次/分钟。

请求使用内部 UUID 预占完整估算金额；报价与倍率快照固定。实际用量、Key/租户扣费、日志、日汇总在同一 SQL 事务提交，重试不重复扣费。失败和未知结果继续占用，避免当作免费空间释放；只在真实异常时提供平台核对入口。估算偏差与上游未知结果不保证绝对零超额。

## 查询与界面

租户查询在服务端限定归属，跨客户详情返回 404。租户只有自己的 Key 页和改密入口；平台页面仍执行后端固定角色检查。视频下载和历史任务也先检查 Key 归属，相同上游任务 ID 不跨 Key 覆盖。

平台账号菜单统一为「账号管理 → 租户账号 / 平台管理员」。首页与 Key 页恢复平台自用 Key 创建；没有租户选择器，不代客户创建。模型广场、价格、巡检和平台日志只向管理员开放。租户经 `GET /api/keys/channels` 只看到本租户可用模型所在的启用渠道：名称、价格倍率、模型价格和健康状态，不含上游地址与密钥；Key 绑定的渠道在服务端校验存在、启用且服务该租户的模型。

只记录必要管理事件：开户、额度、Key、价格、渠道、设置及异常处理。日志、错误、告警脱敏已知凭据；可选正文审计的业务文本仍需要平台自行管理保留范围。

旧 Role 模型和运行授权已删除；迁移保留旧 roles 表和 nullable role_id 供历史核对，自定义旧角色不会提升成平台管理员。旧 Team 演进成 Tenant，没有第二层客户组织。
